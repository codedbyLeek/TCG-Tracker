# Phase 10, Part 1: Pokémon Sync — First Real Data, and an Unplanned API Migration

## Context

Going into this session, `app/sync/pokemon.py` had been written against the pokemontcg.io API but never actually executed. The goal was simple: run it, confirm real Pokémon cards land in Postgres with live prices. What actually happened was a full chain of environment debugging, a live third-party API dying mid-project, a full sync-module rewrite against a new provider, a hand-written Alembic migration, and two clean commits pushed to GitHub. This chapter captures all of it.

## What got built

- `scripts/sync_pokemon.py` — the CLI entry point, written from scratch (it existed as an empty file). Parses a set ID off `sys.argv`, configures logging, opens a `SessionLocal()`, calls `sync_set()`, reports results, closes the session in a `finally` block.
- `app/sync/pokemon.py` — fully rewritten against the **Scrydex API** (pokemontcg.io's official successor) after the original provider started failing with persistent server errors. Handles pagination via a `totalCount`-bounded loop, upserts `Card` rows by `external_id`, extracts a single "best" market price per card from a nested `variants[].prices[]` structure, and writes a `Price` history row per sync.
- A hand-written Alembic migration (`4f4fabc87c75_allow_scrydex_as_price_source.py`) to widen the `prices_source_check` CHECK constraint to permit `'scrydex'` as a valid `source` value.
- Two commits: one isolated typo fix (`requiremnets.txt` → `requirements.txt`), one covering the entire API migration as a single logical unit.

## Key architectural decisions

**Pagination uses `totalCount`, not an empty-array sentinel.** The original design assumed you could tell "no more pages" by requesting one page too many and getting `data: []` back. In practice, at least one real API (pokemontcg.io) returned a `500` instead of an empty array when queried past the end of a small set. The fix: read `totalCount` from the response and stop once `total_fetched >= total_count`, so the loop never issues a request that shouldn't exist in the first place. This is a general pagination principle, not specific to Pokémon data — prefer a known upper bound over "loop until something looks empty."

**Price extraction is a two-phase collect-then-choose, not a first-match-wins.** Scrydex nests prices per card variant (holofoil, reverse holo, etc.), each holding multiple price records across conditions (NM/LP/MP/HP/DM) and types (`raw` vs `graded`). The extraction logic filters to `type == "raw"` and `currency == "USD"` (mixing in graded-card prices or foreign-currency prices would silently corrupt `current_price_usd`), then does a first pass collecting the best price seen *per condition* across all variants, then a second pass picking by condition priority (NM first). A naive single-pass "return on first NM found" would risk locking in a worse price if a card's first-listed variant only has LP data while a later variant has NM.

**`db.flush()` before creating a `Price` row is still required, same reason as before.** A newly created `Card` has no real `id` until its `INSERT` actually executes. `db.add(card)` alone doesn't send SQL — `db.flush()` does, without ending the transaction, which populates `card.id` from Postgres in time for the dependent `Price(card_id=card.id, ...)` insert.

**CHECK constraints can't be edited in place.** Postgres has no `ALTER CHECK CONSTRAINT ... SET condition`. Changing one always means `DROP CONSTRAINT` followed by `CREATE CHECK CONSTRAINT` with the new condition, under the same name so future `alembic revision --autogenerate` runs don't see a phantom diff.

## New concepts covered this session

- **Editor interpreter vs. terminal interpreter** in VS Code are independent settings.
- **Hidden dotfiles** (`.venv`, `.env`, `.git`) don't show in Finder-style pickers by default; `Cmd+Shift+.` reveals them.
- **Python's `logging` module requires explicit configuration** (`basicConfig`) in a script context — it's opt-in, not automatic like `print()`.
- **`sys.argv`** for reading command-line arguments; `sys.argv[0]` is always the program name.
- **The `if __name__ == "__main__":` idiom** — code only runs on direct execution, not on import.
- **Alembic migrations**: what they are (ordered, chained schema-change scripts linked via `revision`/`down_revision`), why they exist (SQLAlchemy models describe *desired* state; migrations are the *path* from old real state to new real state, safely, without discarding existing data), how `alembic upgrade head` walks the chain, and the `alembic_version` bookkeeping table Postgres uses to track current position.
- **CHECK constraints require drop-and-recreate** to change — there's no in-place edit in Postgres.
- **`.gitignore` applies from the repo root down**, regardless of which subdirectory a command is run from — a `.gitignore` "missing" from `backend/` may simply live at the actual repo root instead.
- **Verifying secrets were never committed**: `git check-ignore -v <file>` confirms current ignore status with the exact rule responsible; `git log --all --oneline -- <file>` confirms (or rules out) a file ever having existed in *any* commit on *any* branch — the only way to be certain a secret was truly never captured in history.
